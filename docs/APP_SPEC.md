# APP_SPEC.md

## 1. 문서 목적

본 문서는 iOS 및 Android용 개인 유틸리티 앱(itsolvers-app-001)의 요구사항을 정의한다.

앱의 목적과 범위는 2026-10-15 협의로 정해졌다(3장). 화면 상세와 일부 정책은 아직 **초안**이며 사용자 확인 후 확정한다.

## 2. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | itsolvers-app-001 |
| 앱 유형 | 국내 승용차 가격 조회 |
| 지원 플랫폼 | iOS, Android |
| 프레임워크 | React Native + Expo SDK 57 |
| 프로그래밍 언어 | TypeScript |
| 데이터 저장 | 기기 내부 저장 |

| 배포 | 개인용 또는 내부 테스트 |

> 앱(시작 화면, 웹 제목)의 이름은 2026-10-15에 "승용차 견적 확인"에서 **"리스료 견적"**으로 바꿨다. 리스료를 계산하는 기능은 아직 구현 전이며, 현재는 차량 가격 조회까지만 동작한다.

## 3. 앱의 목적

- 해결 대상: 국내 제조사 승용차의 **차량 → 트림 → 옵션**을 선택하면 가격을 확인한다.
- 주요 사용자: 개인 사용자 (본인)
- 핵심 사용 시나리오: **제조사 → 차종 → 트림 → 옵션(색상 포함)** 순서로 고르면 합계 가격이 계산되어 보인다.
- 성공 기준: 선택한 차량·트림·옵션의 가격이 제조사 공식 사이트의 값과 일치한다. (초안, 확인 필요)

### 범위

- 1단계: 제조사 선택 화면은 두되, 선택 가능한 제조사는 **현대자동차 승용차**(carTypeCode `P`)뿐이다.
- 이후 단계: 기아, 제네시스 등 다른 브랜드를 추가한다. 브랜드마다 사이트 구조가 달라 별도 작업이 필요하다.
- 범위 밖: 중고차, 할부/리스 계산, 견적 저장·공유 (필요해지면 별도 협의)

### 데이터 출처

- 앱이 실행 중에 현대자동차 공식 사이트(`hyundai.com`)의 JSON API를 직접 호출해 가져온다. 서버는 쓰지 않는다.
- 이 API는 사이트 내부용이며 공개·보증된 API가 아니다. 사이트가 바뀌면 앱이 깨질 수 있다. 조사한 호출 흐름은 `docs/ARCHITECTURE.md` 10장에 있다.
- 개인용·내부 테스트 범위에서만 사용한다. 스토어 배포 등 외부 공개 전에 이용약관을 다시 확인한다.
- 가격은 **참고용**이다. 가격이 보이는 화면에 "참고용 가격이며 실제 구매 가격은 제조사/영업점에서 확인해야 합니다"라는 취지의 주의 문구를 항상 표시한다. (정확한 문구는 구현 때 확정)

## 5. 화면 구성 (초안)

구현 상태: 시작, 제조사(+차량가격 직접 입력), 차종(카드), 트림, 가격, 차량 선택 완료(차량 정보 + 리스료 계산) 화면이 모두 구현됨. 차량 선택 완료 화면도 구현됨. 화면 흐름은 시작 → 제조사 → 차종 → 트림 → 가격(사양·옵션·색상 선택) → 차량 선택 완료이다.

| 화면 | 목적 | 이동 |
|---|---|---|
| 시작(랜딩) | 회사 사이트(`itsolvers.co.kr`)처럼 맨 위 왼쪽에 로고와 "아이티해결단"(누르면 회사 사이트가 열림)이 있는 헤더(푸터는 없음). 가운데에 앱 소개와 안내 문구("학습을 위한 것이며 데이터는 정확하지 않을 수 있습니다", 제조사의 공식 서비스가 아님, 데이터 출처). "견적하기" 버튼 | → 제조사 선택 |
| 제조사 선택 | 제조사 선택 (1단계는 현대자동차만). 제조사 줄 바로 아래에 **"차량가격 직접 입력" 줄**이 있다. 제조사 줄과 같은 모양이고, 엠블럼 자리에는 재미있는 로고(금빛 동전)를, 아래 글에는 가벼운 농담("차는 패스! 가격만 쏙 넣으세요")을 쓴다 | → 차종 목록 / → 차량 선택 완료(직접 입력) |
| 차종 목록 | 차종을 카드(큰 차량 이미지와 이름)로 보여주고 선택. 화면이 넓으면 2열 | → 트림 선택 |
| 트림 선택 | 엔진별로 묶인 트림 선택. 같은 이름의 트림(자가용/장애인용 등)을 구분하도록 구매 용도(자가용·렌터카·장애인)와 모델 코드를 함께 표시. 자가용이 아닌 트림은 가격 화면 제목에도 용도를 붙임 | → 옵션/가격 |
| 옵션/가격 | 사양(하나 선택)·옵션(여러 개)·내장/외장 색상(선택 안 함 가능) 선택. 합계 = 사양 가격 + 옵션 + 색상. 하단에 합계, "차량 선택 완료" 버튼, 주의 문구 고정 | → 차량 선택 완료 |
| 차량 선택 완료 | 위쪽: 지금까지 고른 차량 선택 정보(제조사, 차종, 트림, 사양, 선택 옵션, 내장/외장 색상)를 정리해서 보여주고, 그 **마지막에 "차량가격"**(= 사양 가격 + 옵션 + 색상, 항목별 소계 포함)을 보여준다. 아래쪽: **리스료 계산** 입력(기간, 선수금, 보증금, 잔존가치, 금리)과 자동 계산되는 월 납입금액. 저장·공유 기능은 없다 | ← 뒤로(차량 선택을 바꾸려면 가격 화면으로 돌아감) |

차량가격 직접 입력 (2026-10-15 추가)

- 제조사 선택 화면의 **"차량가격 직접 입력" 줄**을 누르면 차종, 트림, 옵션을 고르지 않고 **차량 선택 완료 화면으로 바로** 간다.
- 이 경우 차량 선택 정보(제조사, 차종, 트림, 구매 용도, 모델 코드, 사양, 선택 옵션, 색상, 차량 이미지)는 **아예 보여주지 않고, 차량가격 구역부터** 보여준다.
- "차량가격"은 **직접 입력**한다. 금액 입력 칸(원, 천 단위 쉼표 표시)이고, 처음에는 비어 있다. 차량가격을 입력하기 전에는 리스료 계산 입력(비율 선택 버튼 등)을 보여주되 결과 자리에 "차량가격을 입력해 주세요"를 보여준다.
- 입력한 차량가격은 비율 선택의 기준이 되며, 바꾸면 선수금·보증금·잔존가치 금액과 월 납입금액이 바로 다시 계산된다.
- 직접 입력한 금액은 어디에도 저장하지 않는다.

차량 선택 완료 화면 규칙

- 가격 화면에서 고른 상태 그대로 보여주고, 차량가격은 가격 화면의 합계와 같은 계산을 쓴다. 합계를 화면 맨 아래에 고정해 두지 않고 차량 선택 정보의 마지막 항목("차량가격")으로 보여준다.
- 고른 옵션이 없으면 "선택한 옵션 없음", 색상을 고르지 않았으면 "선택 안 함"으로 표시한다.
- 옵션 선택 규칙을 조회하는 중에는 "차량 선택 완료" 버튼을 누를 수 없다(확인이 끝나지 않은 선택을 정리해 보여주지 않기 위해서).
- 가격 데이터는 오늘 저장된 것을 우선 사용하므로 보통 바로 열린다. 불러오기에 실패하면 오류와 "다시 시도"를 보여준다.

리스료 계산 (차량 선택 완료 화면 아래쪽)

| 입력 | 방식 | 비고 |
|---|---|---|
| 기간(개월) | 12, 24, 36, 48, 60 중 하나 선택 | 처음에는 36개월이 선택되어 있다 |
| 선수금 | **금액(원)을 직접 입력**. 아래 비율 슬라이더(0 … 90%, 5% 단위)로 금액을 빠르게 넣을 수도 있다 | 기본 차량가격의 30%. 장기선수금 |
| 보증금 | 선수금과 같음 (금액 입력 + 비율 슬라이더) | 기본 차량가격의 30%. 만기에 돌려받는 돈 |
| 잔존가치 | 선수금과 같음 (금액 입력 + 비율 슬라이더) | 기본 차량가격의 30%. 만기 시 차량 가치 |
| 금리(연 %) | 숫자 입력(소수 둘째 자리까지). **금리는 직접 입력한다.** | **비우면 계산하지 않고** "금리를 입력해 주세요" 안내 |
| **월 납입금액** | **자동 계산** | 입력이 바뀔 때마다 바로 다시 계산하고, 별도 버튼은 없다 |

금액 입력과 비율 슬라이더 규칙 (선수금, 보증금, 잔존가치 공통)

- 항목마다 **제목이 큰 별도 카드**로 보여서 선수금, 보증금, 잔존가치를 헷갈리지 않게 한다.
- 입력 칸을 누르면 키보드가 올라와도 **입력 중인 칸이 키보드 위에 보이도록 화면이 자동으로 스크롤**된다(맨 아래 금리 칸 포함). 입력 중인 칸은 파란 테두리로 표시된다.
- 숫자 입력 칸(차량가격, 선수금, 보증금, 잔존가치, 금리)을 누르면 안의 숫자가 **모두 선택**되어, 바로 새 숫자를 치면 기존 값이 지워지고 바뀐다. 전체 선택 중에는 파란 선택 배경 위에서 읽히도록 글자색이 흰색이 되고, 입력을 시작하면 원래 글자색으로 돌아온다. 금리 칸도 같다(누른 순간에만 전체 선택하고, 첫 글자를 입력하면 선택 지정을 풀어서 "3.5" 입력 도중 앞 숫자가 지워지지 않는다).
- **금액이 주인**이다. 고객이 "1000만원으로 할게요"처럼 금액으로 말하는 경우가 많아서, 각 항목은 금액 입력 칸(원, 천 단위 쉼표)이 먼저 있고 그 아래에 비율 슬라이더가 있다. 슬라이더를 끌면(또는 막대를 누르면) 차량가격의 5% 단위(0~90%, 눈금 19개) 금액이 칸에 들어가고, 금액을 직접 고치면 손잡이가 "금액 ÷ 차량가격" 비율 위치로 움직인다(5% 단위가 아니면 32.5%처럼 소수 첫째 자리까지 표시). **확대 효과**: 손잡이 위에 지금 비율이 큰 글자(파란 알약)로 떠 있고, 손잡이에 가까운 눈금 점이 크게 보이며, 끌고 있는 동안에는 손잡이와 글자가 더 커진다. 눈금 숫자는 두지 않고, 막대 양 끝 옆에 0과 90만 작게 보여 준다(한 줄을 더 차지하지 않는다). 금액 입력은 90%를 넘겨도 되고, 차량가격을 넘는 값은 계산 검증이 오류 문구로 막는다.
- 비율은 모두 **차량가격 기준**이다. 차량가격이 바뀌어도 입력한 금액은 그대로 두고 비율만 다시 계산한다(금액이 주인). 차량가격이 없으면 비율 슬라이더는 쓸 수 없다(흐리게 표시).
- **처음 값은 세 항목 모두 차량가격의 30%**다. 아직 손대지 않은 동안에는 차량가격이 바뀌면 30% 금액도 따라 바뀌고, 사용자가 금액을 고치거나 슬라이더를 움직인 뒤에는 그 값을 유지한다(0원으로 비워 둘 수 있다). 차량가격이 아직 없으면 비어 있다.
- 계산은 입력한 **금액**으로 한다.

견적 공유 (글자만, 이미지 저장은 하지 않음)

- 월 납입금액이 계산되면 결과 카드 맨 아래에 **"견적 공유하기"** 버튼이 보인다. 누르면 지금 입력으로 만든 글자(제목, 차량 정보, 차량가격, 기간, 선수금·보증금·잔존가치와 비율, 금리, 월 납입금액, "학습용·실제 견적과 다를 수 있음" 문구, 앱 주소)를 보낼 수 있다.
- 앱(iOS/Android)은 휴대폰의 기본 공유창이 열린다(카카오톡, 문자, 메모 등). 웹은 공유창을 지원하는 브라우저(주로 휴대폰)에서는 공유창이, 지원하지 않는 브라우저(주로 PC)에서는 **클립보드에 복사**되고 "견적을 복사했습니다" 안내가 나온다.
- 직접 입력 모드에서는 차량 정보 줄 없이 차량가격부터 나온다. 이미지 저장은 권한 요청과 패키지가 필요해서 하지 않았다.
- 코드: `utils/share-text.ts`(글자 만들기), `utils/share.ts`(보내기).

월 납입금액 계산식 (월 금리 i = 연 금리 ÷ 100 ÷ 12, 기간 n개월, 차량가격 P, 선수금 S, 보증금 D, 잔존가치 R)

1. 기본 리스료 = (P − R ÷ (1+i)^n) × i ÷ (1 − (1+i)^−n). 금리가 0%이면 (P − R) ÷ n. (회사 사이트 리스료 계산기와 같은 식이다.)
2. 선수금 차감 = S ÷ n. 선수금을 기간 동안 **균등하게 나눠 차감**한다. (이자는 따지지 않는다.)
3. 보증금 효과 = D × i. 보증금은 만기에 돌려받으므로 원금은 줄이지 않고, 맡겨 둔 돈의 월 이자만큼 월 납입금을 줄인다. 금리가 0%이면 효과 없음.
4. **월 납입금액 = 1 − 2 − 3**. 1~3을 각각 원 단위로 반올림한 뒤 빼므로, 화면에 보이는 항목별 금액이 월 납입금액과 정확히 맞는다. (한 번에 계산해 반올림한 값과 1원 정도 다를 수 있다.)

입력 검사

- 잔존가치는 차량가격을 넘을 수 없고, 선수금과 보증금의 합도 차량가격을 넘을 수 없다.
- 금리는 0 이상 100 이하여야 한다.
- 계산 결과가 0원 이하가 되면 결과 대신 "입력값을 확인해 주세요" 안내를 보여준다.
- 부가세, 취득세·등록세, 보험료, 정비·수수료 등은 **계산에 넣지 않는다**(단순 계산). 화면에도 이 사실을 표시한다.
- 실제 금융사 견적과 다를 수 있다. 학습용 안내 문구를 함께 보여준다.

공통 화면 틀 (2026-10-15 추가, 같은 날 일부 되돌림)

- **로고 헤더는 시작 화면과 제조사 선택 화면에만** 둔다. 헤더는 왼쪽에 로고와 "아이티해결단"(누르면 회사 사이트), 오른쪽에 "회사 소개" 링크다. **푸터(회사 정보)는 어느 화면에도 두지 않는다**(폰 화면이 작아서 뺐다). (회사 사이트 `itsolvers.co.kr`을 기준으로 한다.) 제조사 선택 화면의 헤더에는 뒤로 가기 버튼과 화면 제목 "제조사 선택"이 함께 있다.
- **제조사 선택 이후 화면(차종, 트림, 가격, 차량 선택 완료)에는 로고 헤더를 두지 않는다.** 폰에서 확인해 보니 화면이 부족해서 되돌렸다. 이 화면들은 앱 기본 제목줄(뒤로 가기 버튼과 화면 제목)과 그 아래 "학습용" 배너를 쓴다. 제목줄 오른쪽 끝에는 작은 회사 로고(누르면 itsolvers.co.kr)를 둔다.
- 웹 브라우저 탭의 **아이콘(파비콘)**은 모든 화면에서 회사 로고다.

이미지와 색상 표시 규칙 (2026-10-15 추가)

- **제조사 엠블럼**: 제조사 선택 목록의 각 행과 차량 선택 완료 화면의 차량 정보에 제조사 엠블럼을 보여준다. 어두운 배경에서도 보이도록 흰 바탕 위에 놓는다.
- **차종 이미지**: 차종 목록의 각 행(작은 이미지), 트림 선택 화면 위쪽, 가격 화면 제목 아래, 차량 선택 완료 화면의 차량 정보에 차종의 옆모습 이미지를 보여준다.
- **색상 표시**: 내장·외장 색상 이름 **앞에 해당 색상을 동그라미로** 보여준다. 글자색은 바꾸지 않는다. 가격 화면의 색상 목록과 차량 선택 완료 화면의 색상 정보에 적용한다.
- 이미지는 모두 **제조사 사이트 서버에서 앱이 실행될 때 불러온다.** 앱이나 저장소에 이미지 파일을 복사해 넣지 않는다.
- 이미지를 불러오지 못하거나 이미지가 없는 차종·색상이면, 이미지 자리는 비워 두거나 회색 동그라미로 보여주고 나머지 화면은 정상으로 동작한다.
- 제조사 엠블럼과 이미지는 제조사의 저작물·상표이므로, 학습용 화면 안내와 함께 쓰고 별도로 수정하거나 재배포하지 않는다.

가격 화면 규칙

- 처음에는 추가금이 없는 사양(기본)이 선택되고, 옵션과 색상은 선택하지 않은 상태다.
- 선택한 사양에서 고를 수 없는 옵션은 흐리게 표시하고 선택할 수 없다. 사양을 바꾸면 새 사양에서 고를 수 없는 옵션은 선택에서 빠진다.
- 옵션 선택 규칙은 제조사 사이트와 같게 적용한다. 선택이 바뀔 때마다 제조사 사이트에서 실시간으로 조회한다.
  - 함께 선택해야 하는 옵션이 있으면 같이 선택된다. 예: 헤드업 디스플레이를 고르면 파킹 어시스트 II가 함께 선택됨. 어떤 옵션이 같이 선택·해제됐는지 안내 문구로 알려준다.
  - 묶여 있는 옵션 중 하나를 해제하면 함께 해제된다. 예: 파킹 어시스트 II를 해제하면 헤드업 디스플레이도 해제됨.
  - 지금 선택한 조합에서 고를 수 없는 옵션은 사유와 함께 비활성으로 표시한다. 예: 다른 옵션을 고른 상태에서는 헤드업 디스플레이를 고를 수 없고, 파킹 어시스트 II를 먼저 고르면 다시 고를 수 있다.
  - 제조사 추가 옵션(튜익스)은 선택한 옵션·색상·다른 튜익스와 맞지 않으면 비활성이 된다. 이미 골랐는데 맞지 않게 되면 자동으로 해제하고 안내한다. 예: 그랜저에서 파노라마 선루프를 고르면 블랙 루프 스킨이 해제됨.
  - 선택 규칙을 조회하지 못하면(오프라인, 서버 오류 등) **선택을 바꾸지 않고** 이전 상태를 유지한다. 확인되지 않은 조합이 합계에 들어가지 않게 하려는 것이다. 화면 하단(합계 위)에 "옵션 조건을 확인하지 못해 선택을 바꾸지 않았습니다. 인터넷 연결을 확인하고 다시 눌러 주세요."와 사유를 표시하고, 다시 누르면 다시 시도한다. 성공하면 안내가 사라진다. 사양·옵션·색상 모두 같은 규칙이다.
- 색상은 제조사가 해당 트림에서 선택 가능으로 표시한 것만 보여준다. 선택하지 않으면 색상 가격은 합계에 포함되지 않는다.

각 화면은 로딩, 오류(네트워크/데이터 형식 변경), 데이터 없음 상태를 가져야 한다.

각 화면의 상세 명세에는 다음 항목을 포함한다. (구현 직전에 작성)

- 화면 목적, 표시할 데이터, 사용자 입력, 사용자 동작, 오류 및 빈 상태, 이동 관계

## 6. 데이터 및 저장 정책

- 데이터는 원칙적으로 기기 내부에 저장한다.
- 앱을 종료하고 다시 실행해도 저장된 데이터가 유지되어야 한다.
- 저장 대상은 사용자 입력이 아니라 **가져온 가격 데이터**와 가져온 날짜다.
- 가져온 데이터는 기기에 **JSON으로 저장**한다. (`expo-file-system` 사용, 구조는 `docs/ARCHITECTURE.md` 6장)
- 갱신 규칙 (협의된 내용)
  - 같은 조건(제조사, 차종, 트림 등)은 **하루에 한 번만** 가져온다. 같은 날 다시 보면 저장된 JSON을 보여준다.
  - 저장된 데이터가 없는 **새로 선택한 조건**은 그때 실시간으로 가져와 저장한다.
  - 날짜가 바뀌면 다음에 조회할 때 새로 가져온다.
  - "하루"의 기준은 기기의 현지 날짜로 한다. (확인 필요)
- 화면에 데이터를 가져온 날짜를 표시한다.
- 앱 삭제, 기기 변경, 데이터 초기화 시 데이터가 어떻게 되는지 사용자에게 명확히 안내한다.
- 백업 및 복원 기능은 별도 요구사항으로 확정하기 전까지 지원한다고 가정하지 않는다.
- 외부 서버로 사용자 데이터를 전송하지 않는다. (제조사 사이트로 가격 조회 요청만 보낸다. 사용자 식별 정보는 보내지 않는다.)

## 7. 비기능 요구사항

- iOS와 Android에서 핵심 기능이 동일하게 동작해야 한다.
- 일반적인 화면 크기와 시스템 글자 크기를 고려한다.
- 사용자 입력을 검증하고 오류를 이해하기 쉽게 표시한다.
- 가격 조회는 네트워크가 필요하다. 오프라인이거나 가져오기에 실패하면 저장된 이전 데이터를 가져온 날짜와 함께 보여주고, 없으면 오류를 안내한다. (확인 필요)
- 데이터 손실을 방지하고 저장 실패를 적절히 처리한다.
- 초보 개발자가 유지보수할 수 있도록 구현을 단순하게 유지한다.

## 8. 테스트 기준

- 차종 → 트림 → 옵션 선택 후 합계 가격이 공식 사이트 값과 일치
- 네트워크 오류, 응답 형식 변경(필드 누락) 시 앱이 죽지 않고 안내 표시
- 같은 날 같은 조건은 네트워크 없이 저장 데이터로 표시되고, 새 조건은 실시간으로 가져옴
- 날짜가 바뀌면 다시 가져옴
- 가져온 JSON이 앱 재시작 후에도 유지
- iOS 및 Android 플랫폼별 주요 동작 확인

실제 테스트 항목은 확정된 기능에 맞춰 조정한다.

## 9. 미결정 사항

다음 항목은 사용자와 협의한 후 확정한다.

- 승용차 범위 (자가용만 할지, 렌터카·장애인용 구분을 포함할지)
- 내장 색상 가격이 0원이 아닌 트림이 있는지 (확인한 트림은 모두 0원)
- 외장 색상이 내장 색상 선택에 따라 달라지는지 (현재는 독립적으로 선택)
- 하루 1회 갱신의 기준 (기기 현지 날짜로 가정)
- 데이터 출처 변경 대응 방식 (사이트가 바뀌어 깨질 때 알림/수정 절차)
- 지원할 최소 OS 버전
- 테스트 기기와 배포 방식

## 10. 개발 범위 관리

최초 버전은 가장 중요한 기능만 포함하는 MVP로 개발한다.

사용자가 승인하지 않은 기능, 외부 서비스, 유료 서비스, 분석 도구는 임의로 추가하지 않는다.

기능 명세가 변경되면 본 문서를 먼저 갱신하고 구현에 반영한다.
