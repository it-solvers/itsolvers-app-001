# APP_SPEC.md

## 1. 문서 목적

본 문서는 iOS 및 Android용 개인 유틸리티 앱(itsolvers-app-001)의 요구사항을 정의한다.

앱의 목적과 범위는 2026-10-15 협의로 정해졌다(3장). 화면 상세와 일부 정책은 아직 **초안**이며 사용자 확인 후 확정한다.

## 2. 프로젝트 개요

| 항목 | 내용 |
|---|---|
| 앱 이름 | itsolvers-app-001 |
| 앱 유형 | 국내 승용차 가격 조회 |
| 지원 플랫폼 | iOS, Android |
| 프레임워크 | React Native + Expo SDK 57 |

| 배포 | 개인용 또는 내부 테스트 |

## 3. 앱의 목적

- 해결 대상: 국내 제조사 승용차의 **차량 → 트림 → 옵션**을 선택하면 가격을 확인한다.
- 주요 사용자: 개인 사용자 (본인)
- 핵심 사용 시나리오: **제조사 → 차종 → 트림 → 옵션(색상 포함)** 순서로 고르면 합계 가격이 계산되어 보인다.
- 성공 기준: 선택한 차량·트림·옵션의 가격이 제조사 공식 사이트의 값과 일치한다. (초안, 확인 필요)

### 범위

- 1단계: 제조사 선택 화면은 두되, 선택 가능한 제조사는 **현대자동차 승용차**(carTypeCode `P`)뿐이다.
- 이후 단계: 기아, 제네시스 등 다른 브랜드를 추가한다. 브랜드마다 사이트 구조가 달라 별도 작업이 필요하다.
- 범위 밖: 중고차, 할부/리스 계산, 견적 저장·공유 (필요해지면 별도 협의)

### 데이터 출처

- 앱이 실행 중에 현대자동차 공식 사이트(`hyundai.com`)의 JSON API를 직접 호출해 가져온다. 서버는 쓰지 않는다.
- 이 API는 사이트 내부용이며 공개·보증된 API가 아니다. 사이트가 바뀌면 앱이 깨질 수 있다. 조사한 호출 흐름은 `docs/ARCHITECTURE.md` 10장에 있다.
- 개인용·내부 테스트 범위에서만 사용한다. 스토어 배포 등 외부 공개 전에 이용약관을 다시 확인한다.
- 가격은 **참고용**이다. 가격이 보이는 화면에 "참고용 가격이며 실제 구매 가격은 제조사/영업점에서 확인해야 합니다"라는 취지의 주의 문구를 항상 표시한다. (정확한 문구는 구현 때 확정)

## 5. 화면 구성 (초안)

구현 상태: 아래 4개 화면 모두 구현됨. 화면 흐름은 제조사 → 차종 → 트림 → 가격(사양·옵션·색상 선택)이다.

| 화면 | 목적 | 이동 |
|---|---|---|
| 제조사 선택 | 제조사 선택 (1단계는 현대자동차만) | → 차종 목록 |
| 차종 목록 | 차종 선택 | → 트림 선택 |
| 트림 선택 | 엔진별로 묶인 트림 선택 (같은 이름의 트림이 있어 모델 코드를 함께 표시) | → 옵션/가격 |
| 옵션/가격 | 사양(하나 선택)·옵션(여러 개)·내장/외장 색상(선택 안 함 가능) 선택. 합계 = 사양 가격 + 옵션 + 색상. 하단에 합계와 주의 문구 고정 | ← 뒤로 |

가격 화면 규칙

- 처음에는 추가금이 없는 사양(기본)이 선택되고, 옵션과 색상은 선택하지 않은 상태다.
- 선택한 사양에서 고를 수 없는 옵션은 흐리게 표시하고 선택할 수 없다. 사양을 바꾸면 새 사양에서 고를 수 없는 옵션은 선택에서 빠진다.
- 옵션 선택 규칙은 제조사 사이트와 같게 적용한다. 선택이 바뀔 때마다 제조사 사이트에서 실시간으로 조회한다.
  - 함께 선택해야 하는 옵션이 있으면 같이 선택된다. 예: 헤드업 디스플레이를 고르면 파킹 어시스트 II가 함께 선택됨. 어떤 옵션이 같이 선택·해제됐는지 안내 문구로 알려준다.
  - 묶여 있는 옵션 중 하나를 해제하면 함께 해제된다. 예: 파킹 어시스트 II를 해제하면 헤드업 디스플레이도 해제됨.
  - 지금 선택한 조합에서 고를 수 없는 옵션은 사유와 함께 비활성으로 표시한다. 예: 다른 옵션을 고른 상태에서는 헤드업 디스플레이를 고를 수 없고, 파킹 어시스트 II를 먼저 고르면 다시 고를 수 있다.
  - 제조사 추가 옵션(튜익스)은 선택한 옵션·색상·다른 튜익스와 맞지 않으면 비활성이 된다. 이미 골랐는데 맞지 않게 되면 자동으로 해제하고 안내한다. 예: 그랜저에서 파노라마 선루프를 고르면 블랙 루프 스킨이 해제됨.
  - 선택 규칙을 조회하지 못하면 안내 문구를 보여주고 제약 없이 선택할 수 있게 한다. (실제로는 함께 고를 수 없는 조합이 될 수 있음)
- 색상은 제조사가 해당 트림에서 선택 가능으로 표시한 것만 보여준다. 선택하지 않으면 색상 가격은 합계에 포함되지 않는다.

각 화면은 로딩, 오류(네트워크/데이터 형식 변경), 데이터 없음 상태를 가져야 한다.

각 화면의 상세 명세에는 다음 항목을 포함한다. (구현 직전에 작성)

- 화면 목적, 표시할 데이터, 사용자 입력, 사용자 동작, 오류 및 빈 상태, 이동 관계

## 6. 데이터 및 저장 정책

- 데이터는 원칙적으로 기기 내부에 저장한다.
- 앱을 종료하고 다시 실행해도 저장된 데이터가 유지되어야 한다.
- 저장 대상은 사용자 입력이 아니라 **가져온 가격 데이터**와 가져온 날짜다.
- 가져온 데이터는 기기에 **JSON으로 저장**한다. (`expo-file-system` 사용, 구조는 `docs/ARCHITECTURE.md` 6장)
- 갱신 규칙 (협의된 내용)
  - 같은 조건(제조사, 차종, 트림 등)은 **하루에 한 번만** 가져온다. 같은 날 다시 보면 저장된 JSON을 보여준다.
  - 저장된 데이터가 없는 **새로 선택한 조건**은 그때 실시간으로 가져와 저장한다.
  - 날짜가 바뀌면 다음에 조회할 때 새로 가져온다.
  - "하루"의 기준은 기기의 현지 날짜로 한다. (확인 필요)
- 화면에 데이터를 가져온 날짜를 표시한다.
- 앱 삭제, 기기 변경, 데이터 초기화 시 데이터가 어떻게 되는지 사용자에게 명확히 안내한다.
- 백업 및 복원 기능은 별도 요구사항으로 확정하기 전까지 지원한다고 가정하지 않는다.
- 외부 서버로 사용자 데이터를 전송하지 않는다. (제조사 사이트로 가격 조회 요청만 보낸다. 사용자 식별 정보는 보내지 않는다.)

## 7. 비기능 요구사항

- iOS와 Android에서 핵심 기능이 동일하게 동작해야 한다.
- 일반적인 화면 크기와 시스템 글자 크기를 고려한다.
- 사용자 입력을 검증하고 오류를 이해하기 쉽게 표시한다.
- 가격 조회는 네트워크가 필요하다. 오프라인이거나 가져오기에 실패하면 저장된 이전 데이터를 가져온 날짜와 함께 보여주고, 없으면 오류를 안내한다. (확인 필요)
- 데이터 손실을 방지하고 저장 실패를 적절히 처리한다.
- 초보 개발자가 유지보수할 수 있도록 구현을 단순하게 유지한다.

## 8. 테스트 기준

- 차종 → 트림 → 옵션 선택 후 합계 가격이 공식 사이트 값과 일치
- 네트워크 오류, 응답 형식 변경(필드 누락) 시 앱이 죽지 않고 안내 표시
- 같은 날 같은 조건은 네트워크 없이 저장 데이터로 표시되고, 새 조건은 실시간으로 가져옴
- 날짜가 바뀌면 다시 가져옴
- 가져온 JSON이 앱 재시작 후에도 유지
- iOS 및 Android 플랫폼별 주요 동작 확인

실제 테스트 항목은 확정된 기능에 맞춰 조정한다.

## 9. 미결정 사항

다음 항목은 사용자와 협의한 후 확정한다.

- 승용차 범위 (자가용만 할지, 렌터카·장애인용 구분을 포함할지)
- 내장 색상 가격이 0원이 아닌 트림이 있는지 (확인한 트림은 모두 0원)
- 외장 색상이 내장 색상 선택에 따라 달라지는지 (현재는 독립적으로 선택)
- 하루 1회 갱신의 기준 (기기 현지 날짜로 가정)
- 데이터 출처 변경 대응 방식 (사이트가 바뀌어 깨질 때 알림/수정 절차)
- 지원할 최소 OS 버전
- 테스트 기기와 배포 방식

## 10. 개발 범위 관리

최초 버전은 가장 중요한 기능만 포함하는 MVP로 개발한다.

사용자가 승인하지 않은 기능, 외부 서비스, 유료 서비스, 분석 도구는 임의로 추가하지 않는다.

기능 명세가 변경되면 본 문서를 먼저 갱신하고 구현에 반영한다.
